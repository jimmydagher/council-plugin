# Strategy cards

Each competitor gets one card: one **lens** (how it reasons), one **shape** (what form the idea takes) and one **bias** (what it optimizes for). The card is the only thing that differs between competitors — the brief is identical for all of them.

## Lenses

| # | Lens | Instruction |
|---|------|-------------|
| 0 | First principles | Strip the idea to the underlying need and rebuild it from there, ignoring how it is usually done. |
| 1 | Inversion | Work out how this idea would fail badly, then design the version that avoids every one of those failures. |
| 2 | Customer's eyes | Start from one specific user's day and pain; every element must earn its place from their point of view. |
| 3 | Constraint-first | Assume half the budget, half the time and half the people; design what still works. |
| 4 | Borrowed analogy | Find an industry that already solved a similar problem and adapt its solution. |
| 5 | Minimum viable | Find the smallest version that proves the idea's core claim within a few weeks. |
| 6 | 10× version | Ask what it would take to make the result ten times better, not ten percent; keep only what is credible. |
| 7 | Contrarian | Challenge the idea's main assumption; propose the version that wins if that assumption is wrong. |
| 8 | Systems view | Map who and what the idea touches (upstream, downstream, incentives) and design for the second-order effects. |
| 9 | Pre-mortem | It is a year later and the idea is quietly abandoned; name why, then design the version that is still alive. |

## Shapes

| # | Shape | Instruction |
|---|-------|-------------|
| 0 | Phased rollout | Deliver it in stages, each useful on its own, with a clear gate between stages. |
| 1 | Platform | Build the shared base others plug into, rather than the one finished solution. |
| 2 | Service | Deliver it as something people do for others (a team, an offering), not as a product. |
| 3 | Partnership | Get it done mainly through another organization's strengths. |
| 4 | Automation | Remove the human steps; people handle only the exceptions. |
| 5 | Process change | Change how people already work, with as little new tooling as possible. |
| 6 | Kill or pivot | Argue for dropping or redirecting the idea, and pitch the better use of the same effort. |
| 7 | Experiment | Frame it as a time-boxed test with a measurable success bar and a stop rule. |

## Biases

| # | Bias | Instruction |
|---|------|-------------|
| 0 | Cheapest | Lowest total cost wins ties. |
| 1 | Fastest | Earliest real result wins ties. |
| 2 | Lowest risk | Smallest downside and easiest rollback win ties. |
| 3 | Most defensible | The hardest-to-copy advantage wins ties. |
| 4 | Simplest to run | Least ongoing effort to operate wins ties. |
| 5 | Biggest upside | Largest potential payoff wins ties. |

## Dealing rule

Competitors are numbered `c01` … `cNN` (N ≤ 16). Competitor *i* (counting from 0) gets:

- lens `i mod 10`
- shape `i mod 8`
- bias `i mod 6`

With these list sizes this guarantees, for any N up to 16: no card repeats, each list is spread as evenly as possible, and no two competitors share more than one part. If you change a list size, re-check those three properties before using it.
